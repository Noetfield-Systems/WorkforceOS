# WorkforceOS — Hybrid Commerce, Agent Studio and Participation Economy
Founder Architecture Amendment v1 | 2026-11-17 | WorkforceOS-owned

## 1. Permanent portfolio classification

Noetfield Corporation is a software-infrastructure business; it is NOT inherently Web3-native, an onchain company, or a token issuer. Its separately scoped Onchain-OS may adopt blockchain functionality without tokenizing the corporation. Every portfolio venture retains separate legal seller, data, wallets, policies, payment accounts and outcomes.

WorkforceOS is a HYBRID-COMPATIBLE, SOFTWARE-FIRST BUSINESS and an independent venture/Company OS context. The primary product is a real AI workforce: discover an expert agent, configure its DNA, save, run authorized work, inspect the real result, test, improve and eventually purchase commercial access. Web3 compatibility is OPTIONAL and must not wallet-gate basic software access. Community is a SECONDARY flywheel earned through product utility, not a replacement for engineering or a pure community-only website.

Web3-native ventures (including ARQANT and other independent token/reward projects) may have token, referral, quest and season economics under their own venture rules. No token, wallet or economic entitlement crosses those venture boundaries by implication.

## 2. Product and revenue thesis

Positioning: "Build your AI team. Run real work. Grow your business."

WorkforceOS sells a functional AI working environment, not animated avatars or model prompts alone. Its Agent Marketplace offers real customer-configurable specialist profiles. Its Agent Studio builds versioned identity, ethics, skills, knowledge, runtime requests and operating instructions. Agent Fabric, HDIR, Runway and the Independent Verifier remain the SINGLE execution and evidence chain; never create duplicate runtime engines, a CRM, payment source ledger or Company OS.

Commercial models, separated by ownership and evidence:
- Platform subscription and usage: existing authorized Stripe billing in app/billing.py. Historical application configuration lists Solo USD29/month, Builder USD79/month, Team USD199/month. Those are source code amounts, not verified collected money or approved external SKU rollout. Access may only be enabled by verified entitlement state.
- Paid Agent/creator marketplace: future explicit SKU, actual fulfillment/license contract, buyer checkout, source webhook, refund handling and approved provider recipient payout. Current public templates are FREE; paid creator listings, Connect transfers and revenue shares are NOT LIVE.
- Managed build/enterprise setup: scope and real service delivery must be attached to an actual paid contract, tenant and independently verifiable receipt.
- Crypto/stablecoin checkout: optional ONE-TIME verified payment route for clearly scoped offers; never silently invent a recurring subscription or company token.

Stripe findings from Production variable readback, 2026-11-17: WorkforceOS Railway service did NOT contain STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET or the three configured Stripe price IDs. Existing hosted checkout/portal/HMAC webhook code cannot charge genuine buyers without that legitimate merchant configuration. Stripe account NOETFIELD SYSTEMS INC. may be connected separately, but do not assume it is automatically the merchant of record for independent WorkforceOS obligations. Connect the legally correct seller/account before installing payment secrets.

Crypto: A provider-only marketing button or unverified wallet transfer is NOT checkout. Select authorized WorkforceOS merchant recipient, network, native asset, settlement model and applicable rules. For a Base USDC option, verify current native Circle USDC contract from the issuer; ensure quote accuracy, chain ID, sender-to-invoice binding, recipient, exact token/amount, confirmations/finality, unique transaction/event claim, idempotency, refunds and entitlement. Do not represent either route as available to a Canadian merchant without explicit account eligibility verification.

For payment collection require: legitimate seller + contract/price + authenticated buyer workspace + hosted/bounded Checkout + provider-signed verified event + correct tenant entitlement + actual task/product delivery + independent receipts. Refund, failure and chargeback adjust entitlements and earned amounts; checkout click, wallet connection or pending transaction never count as sale.

## 3. Five different records — never merge them

A. Actual payment source: verified Stripe or future onchain source receipt; processor owns collected/settled amounts.
B. Tenant entitlements: derived access/subscription/usage rights after verified payment, separate from money movement.
C. Runtime costs: provider-logged token/task expense and independent execution receipts.
D. Internal participation XP: non-transferable, non-purchasable, no cash value, no discount/service credit, NO future token/airdrop entitlement.
E. Creator earnings: only contractual/fulfilled paid charges; separate pending/earned/payable/paid/reversed and provider payout receipts.

Company OS aggregates independent references, not cloned ledgers. No fake ratings, payouts, external customers, balances, job success, token allocations or revenue.

## 4. Studio technical operating contract — implemented v1 delta

Agent DNA already includes identity, mission, role, backstory, tone, personality traits, chosen values, skills, permitted knowledge references, requested tools, autonomy and economy/balanced/quality model preference; all versioned in the current tenant-owned manifests. Actual tasks flow through existing Fabric. New advanced typed DNA fields:
- ethics.evidence: source-first, balanced, explicit uncertainty.
- ethics.privacy: minimal data, authorized workspace context, approved sources.
- ethics.escalation: material uncertainty, external action authorization, human review.
- ethics.sensitive_actions: never or propose-only.
- output.format: structured Markdown, plain text, JSON-style outline (NOT hard-constrained JSON generation).
- output.detail: concise/standard/comprehensive.
- output.review: self-check or independent-review request.
- output.citation_mode: source links when available or source IDs when supplied.
- model_provider_request: Auto / Cloudflare Workers AI / DeepSeek / Hugging Face / OpenAI / Other.

Policy and output instructions are saved, validated, versioned and compiled into the actual Agent Fabric instruction payload, with tenant auth and CSRF. Provider selection, raw completion parameters, live model overrides and requested tool grants are explicitly NOT currently enforced: metadata request only until the existing HDIR and Governor authorize and implement them. Selection must NEVER grant credentials or bypass scopes. Run the real test lab, use source-backed outputs and preserve the independent verifier boundary.

Next technical WorkPacket: add typed model-route and budget/timeout limits at the EXISTING HDIR/Agent Fabric authorization seam; validate provider availability, hard usage caps, tenant permission, cost, fallback and evidence. Do not create a second Agent Runtime or a fake model settings widget that claims to change execution before the interface supports it.

## 5. Internal XP activation, with real ledger

The WorkforceOS participation_points table is tenant scoped with immutable positive awards and uniqueness of workspace+claim_key. Award only after recorded first-party activity:
- Daily authenticated check-in: +5 XP once per UTC day.
- First actual saved Agent DNA record in workspace: +20 XP once, in the same database transaction as agent creation.
- Substantial submitted product feedback: +10 XP once per UTC week, recorded in the existing product_feedback route.
- Correct tool-authority quiz: +15 XP once per workspace; a wrong answer does not earn points.

The public API describes the non-financial policy and the private API returns actual earned balance/history; anonymous users cannot claim. No token, cash, service credit, airdrop, guaranteed prize or promised conversion. Gift, invite, referral, daily streak, sponsored quests and paid discounts are separate future modules requiring a verified referral/anti-abuse/contract rule. Do not mint XP on fictitious task results, self-claimed sales or prompt volume.
